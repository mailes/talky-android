# Building Talky for Android

## Toolchain

Use JDK 17, Android SDK/compile API 36, Build Tools 36.0.0, NDK 27.2.12479018 and CMake 3.22.1. The wrapper pins Gradle 8.13 and the root build uses Android Gradle Plugin 8.13.2. Run `git submodule update --init --recursive` before building. Prebuilt native dependencies are included alongside their build scripts and pinned source references.

Set the Android SDK path in ignored `local.properties` (`sdk.dir=/absolute/path/to/android-sdk`). Set `JAVA_HOME` to JDK 17. If a global `~/.gradle/gradle.properties` overrides `org.gradle.java.home`, also pass `-Dorg.gradle.java.home=/path/to/jdk17`.

## Private build settings

Copy `private-build.properties.example` to `private-build.properties`; the latter is ignored. Supply your own `TALKY_API_ID` and `TALKY_API_HASH` for authentication. Without configuration, they build as zero/empty values and are not usable login credentials.

The same named environment variables and `-P` Gradle properties are supported. Do not put secrets on shared command lines or logs. Prefer the ignored file or environment variables, restrict file permissions, and keep private keys outside the checkout.

Optional Google Maps, SafetyNet/Google identity and Huawei settings are blank by default. They require your own provider setup. Inherited Firebase/Huawei project files are not distributed. The website standalone target does not apply the Firebase plugin; other store variants need their own service configuration.

## Debug build

```sh
scripts/build-android.sh debug
# Equivalent:
./gradlew :TMessagesProj_AppStandalone:assembleAfatDebug
```

Output: `TMessagesProj_AppStandalone/build/outputs/apk/afat/debug/talky.apk`.

Android's generated debug keystore is used, with the standard debug credentials rather than the Talky release key. The standalone debug application ID ends in `.debug`, so it does not overwrite the installed official app. For a rebranded fork, also override `APP_PACKAGE`, for example `-PAPP_PACKAGE=com.example.myclient`.

## Signed standalone release

Set these private values:

- `TALKY_RELEASE_STORE_FILE`: absolute path to your existing keystore outside Git.
- `TALKY_RELEASE_STORE_PASSWORD`
- `TALKY_RELEASE_KEY_ALIAS`
- `TALKY_RELEASE_KEY_PASSWORD`

```sh
scripts/build-android.sh release -POWPENGRAM_BUILD=9
# Equivalent:
./gradlew -POWPENGRAM_BUILD=9 :TMessagesProj_AppStandalone:assembleAfatStandalone
```

Output: `TMessagesProj_AppStandalone/build/outputs/apk/afat/standalone/talky.apk`.

The version name and base code come from `gradle.properties`; the universal flavour adds ABI code 9 (`7304 * 10 + 9 = 73049` for O9). `OWPENGRAM_BUILD` is the separate in-app update sequence; its local default is 0, which disables release update checks. Use your own update feed for a fork, rather than increasing the official Talky feed number.

An existing app can only upgrade in place when package identity, signing identity and version ordering are compatible. Keep the official signing key unchanged when publishing an official Talky update. A key built or generated by a contributor cannot sign an update to the official app.

Retain R8 mapping output for release crash deobfuscation. Verify package, version, signature and architecture before publishing. A successful source build alone does not validate runtime behaviour or deployment.

On Windows, `build-android.bat` and `scripts/build.ps1` are thin wrappers for these same Gradle tasks. They read the same local settings and do not patch credentials into tracked Java source.
